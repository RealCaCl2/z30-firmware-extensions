## 实机操作

1. 按既有 EG 加载流程载入本页产物。进入照片画幅，启用 4:3 或 5:4。
2. 返回取景，分别开启、关闭原厂参考线，各停留约两秒，复现没有黄色边框的情况。无需另拍照片。
3. 再进入一次“照片画幅”子菜单，触发已有的空闲日志导出。
4. 提供存储卡根目录的 `WL-ASPECT.DBG`。v18 及更早文件没有本次计数，需使用本版重新导出。

本地文件：`output/full-aspect-border-diagnostic-v19/EG209020.BIN`。

SHA-256：`46fd69661eb12105b26200f5fe88f13f5f8fd03c615ba4cb1704bc1448991ba5`。

它是 EG 模块，不是 Nikon 外层更新容器。本轮没有向相机或物理卡写入文件。

## 新记录

沿用 WAD1 格式 4、96 槽、15384 字节。事件 5 原有 64 字节字段不变，尾部增加 `WBD1`、版本 1、16 个累计计数，以及导出采样时的矩形通道/原厂网格开关值。旧版本文件仍可读取；新尾部由更新后的 `read_aspect_trace.py` 识别。

| 计数 | 用途 |
|---|---|
| `monitor` / `grid_updater` | 分别确认候选监视入口和已工作的原厂网格更新入口是否执行 |
| `publish` / `inactive` | 发布函数是否进入，是否因画幅未启用退出 |
| `display_busy` / `photo_not_ready` | 显示或照片可用条件拦截 |
| `rectangle_channel_disabled` | 原厂矩形通道启用检查拦截 |
| `snapshot_not_ready` / `projection_rejected` | 快照或投影检查拦截 |
| `unchanged_request` | 比例/视口签名未变，重复请求被抑制 |
| `request_attempted` / `rectangle_producer` | 分开记录尝试发布与真正执行打包器，不能把前者视为送达 |
| `apply` / `apply_rejected` | 追加函数是否进入，以及是否跳过 |
| `free_records_insufficient` / `apply_succeeded` | 空闲位置不足，或确实填入边框记录 |

计数位于扩展自己的额外 64 字节状态中，仅随本次 RAM 会话累计；不记录像素、文件名、身份或任意内存。计数不是事务快照，不能据此还原多线程严格顺序。采样时的通道值可能受菜单状态影响，不能当作此前取景瞬间的值。

没有高频文件写入。仍在重新进入子菜单、且非忙碌时用既有方式导出。生产器/发布函数只增加 RAM 计数，不修改传入/返回值。

## 本地核对与边界

证据目录：`build/research/aspect-border-v19/`，报告绑定本页 SHA-256。

- 新探针先从通道关闭状态执行：没有请求、关闭拦截计数增加；再以显式启用状态执行：尝试请求计数增加，但生产器计数仍为零。随后手动执行生产器，才出现追加成功。这三个阶段分别核对，避免混为端到端成功。
- 执行新菜单采样和解码，确认先前拦截计数在后续成功后仍保留，文件格式/长度不变，导出中能区分原厂网格值与通道值。
- 同一文件通过原有 96 项边框组合、8 项守卫、63 项主几何、1680 项预览选择器、36 项组合网格、格式 4 处理/导出和 59 项单元测试。QEMU 经正常父菜单完成 4:3／5:4／关闭及区域联动，三档导出均含新计数。默认 v17 与未开诊断的 v18 构建仍逐字节一致；这些检查不能证明物理边框可见。

```powershell
python tools/build_aspect_border_trial.py --source Z_30_0120.bin `
```
