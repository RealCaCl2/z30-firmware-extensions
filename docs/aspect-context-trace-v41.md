> 2026-10-18：[v42](aspect-lifecycle-v42.md) 增加原厂取景阶段限制，并在绘制目标筛选之前清除旧遮幅。用户在本次回放修复复测后反馈“正常了”，记录为本次问题获机身确认；未提供逐档或完整生命周期覆盖。v37、v40 的失败及 v41 定位记录保留。

**v40 机身复测失败。** 用户反馈：“照片回放还是会被裁切成设置的画幅”。仅停用遮幅入口的对照此前已获正常反馈，恢复入口后 v40 的条件守卫仍不足。不能继续把照片后端就绪当成正在拍摄取景的证明。

**本页 v41 是定位模块，不是修复版，预期仍能重现 v40 的问题。** 它保留 v40 的遮幅判断、填充和清除，记录实际界面切换时的状态，为下一次修复提供机身证据。本轮未连接相机或写存储卡，也未 commit/push。

## 需要的机身操作

1. 按已有流程加载本版并重新启动，设为 **4:3**，回到拍摄取景停留约三秒。
2. 普通回放一张原本为 DX 的旧照片，重现当前画幅裁切；放大后再缩回普通回放。
3. 返回拍摄取景，再进入自定义菜单的“照片画幅”子菜单，停留一秒。为避免恰好遇到正在写记录的回调，可退出子菜单再进入一次。
4. 读取存储卡根目录最新的 **`WL-ASPECT.DBG`**，交回分析。不需要提供原始照片。

这次先保持 4:3 选择，避免额外的多档/待机/重启操作挤掉需要的状态。导出会覆盖同名诊断文件；没有照片读写或照片内容记录。若文件没有更新，返回上级后再进入画幅子菜单。文件格式以 `WMD1` 开头，长度 8,216 字节；旧的 `WAD1` 拍摄日志不能代替本次记录。

## 记录内容与边界

- 图形回调只把数值存入私有 RAM；不调用文件服务、不等待菜单或其他线程。它利用 v40 已有的非阻塞遮幅锁串行记录。
- 每条包含序号、当前比例、v40 遮幅条件的结果及 20 个已定位标量读数：视图种类、照片后端、就绪位、原厂 UI 属性、服务阶段、显示源、DISP 页、图像表面地址、视口和源窗口坐标。没有图片、文件名、EXIF、任意对象转储或个人路径。
- 这些字段尚不能命名为“相册状态”。原厂读取来源写在 `aspect_mask_trace.py`；不把未知 UI 属性解释成已经证明的应用身份。
- 连续相同状态不新增记录，最多保留最后 64 个不同状态。状态是顺序采样，不是对所有服务加锁的原子快照。
- 进入画幅子菜单时冻结记录；若生产者锁忙或相机忙，立即跳过导出。文件操作只在菜单任务中进行，正常/错误路径均解除冻结。
- `aspect_trace=True` 与动态遮幅组合时使用这一独立格式，RAM 位于已有 128 字节遮幅记录之后。旧的拍摄诊断模式仍使用原格式；普通无遮幅诊断构建的行为保持。
