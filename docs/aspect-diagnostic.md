## v10：记录真实处理请求与参数

常规构建仍不启用日志；显式 `aspect_trace=True` 才加入以下两个入口：

- `0x102507CA`：先执行完整原厂参数转换，再记录 `+0x384` 起的 144 字节标量参数；保留原厂返回值和结构内容。

## 诊断版的范围

`build(..., aspect_trace=True)` 是显式开发选项，常规 CLI 和默认构建不启用它。专用构建工具为 `tools/build_aspect_diagnostic.py`。

- 在已分配的扩展状态内存中记录 64 条、每条 160 字节的有界循环记录。
- 事件 1 记录真实输出尺寸选择器的调用地址、输入区域/尺寸、返回宽高和调用者保存寄存器。
- 事件 2 记录原厂普通配置函数经过 `0x10142A22` 时的捕获标志和 112 字节几何。实际拍摄若未经过该路径，日志可以帮助区分这一情况。
- 拍摄/几何回调不调用文件服务。不复制图像，不读取任意指针指向的内存。
- 进入扩展“照片画幅”子菜单且原厂 busy 状态允许时，暂停记录，导出 `A:\WL-ASPECT.DBG`，然后恢复记录。导出覆盖同名专用日志，不改 JPG。
- 保留 v5 成像逻辑，不叠加新裁切猜测。这个诊断版本仍可能产生瘦长图像。

## 解码与重建

```powershell
python tools/read_aspect_trace.py path/to/WL-ASPECT.DBG --output build/research/aspect-diagnostic-v6/camera-trace.json
python tools/build_aspect_diagnostic.py --source Z_30_0120.bin --deps ../tools/vendor --output output/my-aspect-diagnostic/EG209020.BIN
```

文件为小端：24 字节头 `(magic=WAD1, version=1, counter, capacity=64, stride=160, freeze)`；随后 64 个记录槽。记录头为 `(commit_sequence, event, profile, caller)`，后接最多 144 字节负载。sequence 在负载完成后发布。记录器使用有界 LDREX/STREX 申请序号；导出时冻结记录，因此不需要在拍摄回调中等待文件写入。

输出 getter 的负载为 8 个 u32：area、size、pointer、packed_WH、调用者 R4–R7。普通配置负载为 8 个捕获信息字，后接 112 字节配置。不得把主机测试生成的诊断地址或参数当成真机记录。

## 验证边界

`tools/verify_aspect_trace.py` 执行构建出的 ARM 记录器：循环覆盖、冻结、超长负载拒绝、真实输出 hook、完整普通配置快照、空闲导出、busy 跳过和写入失败解除冻结均通过。文件服务为模型；真实存储卡与实际拍摄调用点尚待机身日志确认。

常规几何、88 个源窗口守卫、1680 个预览调用守卫、参考框和项目测试也需保持通过。QEMU 使用独立的大日志文件服务夹具，不能让 10264 字节日志覆盖原有 16 字节配置夹具。

本地证据目录：`build/research/aspect-diagnostic-v6/`。原始样片分析目录：`build/research/aspect-seven-samples/`。它们均被版本库忽略。

QEMU 补充：首次两轮因新增模拟文件服务将 ARM memcpy 按 Thumb 调用而失败，已修正夹具为 ARM 调用；它们不是成功证据，也不能用其闪存停止推断真实相机故障。最终 `qemu-hans-fixed-fixture/` 会话通过正常父菜单、4:3/5:4/关闭动作、真实 getter 的诊断调用，以及子菜单导出的10264字节日志解析。没有使用 seeded-state 的 export-only 路径作为最终成功证据；SD 仍为模拟服务，实际拍照仍待真机。

## 第一份真机日志与 v7 记录策略修正

用户提供的 v6 `WL-ASPECT.DBG` 成功导出，解析头 counter=50539。末尾64条全部处于 profile 4（2.35:1），其中58条来自 `0x10132247`、5条来自 `0x100AEA9B`，另1条来自 `0x103669F7`。前两项为高频图像/取景查询，普通循环缓存被覆盖。因此这份日志不能证明狭画幅拍摄没有执行普通配置路径，也不能据此认定新根因。

已修正诊断记录本身，不要求用户为同样的噪声再重复采样：v7 文件版本字段为2，保持总长10264字节、64个槽、每槽160字节。

- 槽0–6分别固定保留每个 profile 的最后一份事件2配置，不受输出查询环覆盖。
- 槽7–63为57条输出查询环；仅记录 profile 0/1/2，排除两处已被真机证实的高频调用者 `0x10132247`、`0x100AEA9B`。
- 解码器同时支持旧v1与新v2。配置固定槽允许旧序号；输出环仍检查序号和槽位对应关系。
- 本地验证固定配置在100次后续输出记录覆盖后仍保留，并检查两类噪声与其他 profile 不推进输出记录计数。

v7 不追加新的裁切猜测，成像逻辑仍与v6相同。该诊断方案后来暂停，未要求继续测试 v7；当前使用不带日志的 v8。

原始日志副本与解析结果在 `build/research/aspect-diagnostic-v6/camera-WL-ASPECT.DBG` 和 `camera-trace.json`；v7验证在 `build/research/aspect-diagnostic-v7/`。不修改存储卡上的原始文件。
