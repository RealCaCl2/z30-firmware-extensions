# Z30 自定义画面比例遮幅：可行性与实现方案

日期：2026-10-13。范围：Wonder Lantern 的 Nikon Z30 C 1.20 实时取景构图辅助。

## 结论

**具备继续开发的技术基础，但尚未证明实时取景遮幅可用。** 当前更接近实现的是画幅参考框；黑色与半透明遮幅需要接入原厂实时取景绘制上下文，不能仅修改网格坐标就宣布完成。

计算比例与矩形的成本很小，已有菜单、设置保存和原厂图形系统提供可复用基础。目前没有证据表明硬件性能构成阻碍；决定性缺口是正确的绘制回调、叠加层生命周期和输出通路。没有性能测量，不能承诺特定帧率。

建议第一版交付关闭、参考框、黑色遮幅三种模式，比例为 1:1、4:3、16:9、2.35:1、2.39:1、9:16；先打通一个 2.35:1 黑色遮幅，再增加菜单选项。半透明模式在混合与状态恢复确认后加入。自定义比例采用整数分子/分母；不解析浮点文本。

本方案只定义显示叠加。照片和视频裁切需要另立编码/文件输出方案。要保证录制文件不含黑边，仍必须追踪叠加表面的消费者并检查实机文件。

## 路线选择

### A. 原厂网格参数：参考框实验

已恢复的 32 字节结构 `<hhIHHhhIHHHHBBH` 包含横/竖线起点、长度、间距、数量、颜色和共享笔画宽度。可尝试两条横线和两条竖线表达一个完整参考框，复用已有请求、bank、任务消费和对象归还。

关键限制：

- 数量 0 会经过 `count-1` 下溢，寄存器数量字段得到 7，不能用它关闭单轴。
- 原厂验证器会拒绝奇数起点，必须遵守已观察到的坐标对齐约束。
- 两轴共用笔画宽度，不能直接用上/下和左/右不同厚度来生成通用遮幅。
- 当前只确认原厂细线条件；粗线、颜色与透明度范围需要另行确认。
- mode 0/1/2 的 mask 1/2/4 没有已证明的 LCD/HDMI 物理身份。
- 借用原厂网格会影响其共存行为，必须明确选择替换或独立绘制；不能静默改掉用户的网格设置。

因此 A 适合作为坐标与更新时机探针，不能作为黑色遮幅完成的依据。

### B. 原厂图形叠加层：遮幅实现主线

从实时取景的绘制对象和提交链寻找已有有效图形上下文的回调，在该上下文中画四个填充矩形。优先复用原厂矩形绘制或填充路径；确认混合方式后支持半透明黑色。

需要确认的合同：目标表面、当前 bank、坐标系、绘制顺序、裁剪、矩阵、颜色/混合状态，以及提交后资源何时可复用。入口发现阶段先记录这些值，不直接写未知显示寄存器。

原厂取景图形通常还包含曝光、对焦、水平仪等控件。应先定位背景/辅助图层顺序，使遮幅遮住取景图像而关键状态仍可读；具体能否分层必须由实际调用链确定。每次绘制都恢复修改过的状态，保持原厂回调的返回值、寄存器和栈合同。

历史菜单像素上传研究只说明存在可追踪的原厂图形前端，无法确定实时取景表面；不直接移植菜单 painter、定时器槽或旧模块代码。

## 坐标算法

输入是**当前有效图像区域** `V=(x,y,W,H)`，不是整块 LCD 尺寸，也不是编码分辨率。必须区分照片、视频、信息显示边距、放大取景、电子防抖裁切和输出变换。矩形字段 `104B9348` 快照 `+8/+14` 是候选来源，尚需识别各字段的实际用途。

目标比例 `p:q`，要求 `p>0,q>0`。以 64 位整数比较 `W*q` 与 `H*p`，在 V 内取最大居中矩形：

```text
若 W*q >= H*p：h=H，w=floor(H*p/q)   # 遮左右
否则：         w=W，h=floor(W*q/p)   # 遮上下
x0=x+floor((W-w)/2)
y0=y+floor((H-h)/2)
```

按实际绘图接口要求向内量化有效矩形，并记录量化后的比例误差。网格路线已观察到偶数起点要求，不据此推断所有 GPU 路径都需要相同对齐。为保持两边对称，必要时把尺寸量化到更小的步长；所有端点仍须限制在 V 内。

采用半开区间避免边界重复混合。四个互不重叠的遮幅矩形为：

```text
上：(x,  y,    W,      y0-y)
下：(x,  y0+h, W,      y+H-y0-h)
左：(x,  y0,   x0-x,   h)
右：(x0+w,y0,  x+W-x0-w,h)
```

宽/高为零的矩形跳过。不同接口若采用端点而非尺寸，转换时单独处理。

以下只是 `720×480` 有效区域、局部原点为零时的几何示例，采用尺寸向下取 4 的倍数以得到偶数居中起点；不是实机视口测量：

| 比例 | 居中有效矩形 | 遮幅 |
|---|---|---|
| 1:1 | `(120,0,480,480)` | 左右各 120 |
| 16:9 | `(0,38,720,404)` | 上下各 38 |
| 2.35:1 | `(0,88,720,304)` | 上下各 88 |
| 2.39:1 | `(0,90,720,300)` | 上下各 90 |
| 9:16 | `(226,0,268,480)` | 左右各 226 |

旋转支持必须以原厂显示变换为依据；视频旋转元数据功能不能证明 LCD 坐标已旋转。第一阶段支持居中构图，偏移构图后续独立加入。

## 状态、配置与集成

建议新增独立 `aspect-mask` 特性，ROM 中保存比例表和版本校验；RAM 状态包含模式、分子/分母、透明度、会话代号、视口和待重绘标记。菜单只发布配置，图形任务读取一致快照并绘制。

默认关闭。配置保存复用现有 SD 记录的完整读写和错误处理方式，使用独立文件、版本与校验，不复用声音/码率字段，不占用未确认的原厂属性编号。恢复失败时回到关闭并允许重新设置。绘制回调中不做 SD I/O、分配内存或等待长时间锁。

进入取景并取得有效上下文后启用；比例、视口和模式变化标记重绘。关闭、菜单/回放切换、放大取景、休眠和退出先停用本次会话，再请求原厂重绘。尚未确认的视图暂时关闭遮幅；迟到回调用会话代号拒绝。不能靠“以后不再画”清除旧像素，应定位旧区域擦除或原厂完整重建机制。

当前模块 ABI 缺少需要的回调合同，第一版采用内置特性更直接。待取景生命周期明确后，再设计版本化模块显示 API。接入 `FEATURE_ORDER` 时同步审核 `full`、组合预设、菜单和文档；实验阶段不自动加入所有用户构建。

## 开发与验收顺序

1. **定位上下文。** 从 `104BE422` 和图形 worker 追踪真实调用者、刷新触发及 bank 身份，记录活动视口和绘制上下文。完成条件是确定可用的取景回调与退出路径。
2. **最小显示探针。** 实际客体回调画一个小矩形，确认每次原厂重绘后仍存在；关闭和退出均由原厂重绘清除。禁止用主机截图后加工替代客体绘制。
3. **固定 2.35:1。** 使用实际视口画上下黑边，检查状态控件层级、连续更新与菜单/回放恢复。随后扩展四边遮幅和配置菜单。
4. **执行与 QEMU 诊断。** 检查比例极值、不同原点、对齐、失败关闭、旧回调拒绝和资源回收；观察客体 GPU 提交与像素。QEMU 的 LCD 合成、YYUV422A/alpha、色彩转换和帧节奏有模型假设，报告必须标明。
5. **实机核对。** 照片/视频取景、开始/结束录像、各 DISP 页、网格/直方图/水平仪/峰值共存、放大、回放、待机和唤醒。实机视口、显示稳定性、录制文件无黑边分别记录。
6. **输出策略。** 第一版只在确认身份的 LCD 通路启用；HDMI 有连接时的条件与关闭机制仍需确认。HDMI 显示和录制编码链分别检查后再扩展，不能从 mask 编号或 QEMU 合成结果推断。

本次交付为静态研究与设计文档，没有新增可刷包、实时取景执行报告或实机确认。下一步最有价值的工作是找到有效的取景绘制回调，并完成可开启、可清除的最小矩形探针。
