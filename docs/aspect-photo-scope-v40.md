# v40：取景遮幅的应用条件与残留清除

日期：2026-10-18；机型 Nikon Z30 C1.20。

用户确认[仅停用遮幅入口的对照](aspect-playback-mask-control.md)“这下正常了”。该对照与 v37 仅有 GPU submit 的 10 字节入口窗口及 CRC 不同，因此新增遮幅入口参与了普通回放异常。透明度不同不足以排除该入口；机身黑边变为不透明的完整合成过程仍未证明。

**最新：[v42](aspect-lifecycle-v42.md) 增加原厂取景阶段限制，并在绘制目标筛选之前清除旧遮幅。用户在本次回放修复复测后反馈“正常了”，记录为本次问题获机身确认；未提供逐档或完整生命周期覆盖。v37、v40 的失败及 v41 定位记录保留。**

## 实现

1. 遮幅入口增加原厂照片叠加层条件的照片子集：视图种类为 0/6，两个原厂叠加忙标志为零，照片后端为 1，视口快照的就绪位存在。对应原厂 `0x104BE4A0`、`0x10306328` 的读取条件，投影前和实际写入前分别检查。不从 GPU 工作线程调用原厂快照锁，不读取网格偏好。显示源标志和目标尺寸不能单独证明处于拍摄取景。
2. 在已有 16 字节画幅设置之后增加 128 字节私有 RAM，记录上次下层表面、矩形、颜色和有效标志。设置文件仍为原格式；随后声音子页的位置随分配顺延，不与历史记录重叠。
3. 自定义回调使用至多四次尝试的非阻塞锁，串行管理自己的记录。相同表面和矩形的连续帧直接填充；比例、几何、就绪条件改变或关闭功能时清理旧记录。
4. 清除只处理同一当前表面、先前矩形内仍等于本版遮幅颜色的像素。原厂已改写的其他颜色和不透明黑色保留；表面指针更换后不解引用旧表面。没有整屏清零或擦除上层原厂 UI。该锁只约束自定义 CPU 回调，不能据此宣称物理 GPU/缓存并发合同已证明。
5. 保留 alpha `128/255`、v36 外缘补缝与成片投影、网格独立性、分类菜单和 v37 文件几何查询隔离。成片几何表与 v37 逐字节相同。

相关源码：`src/z30_extensions/features/aspect_mask.py`、`aspect_ui.py`。构建报告 `soft_mask.version=11`，包含条件字段、状态分配和清除策略。

## 被否决的中间版本

- v38 用 `0xC18200DC == 1` 限定显示源，QEMU 正常取景无法显示遮幅；已撤回，不交付。
- v39 仅增加照片条件，拒绝新绘制后仍留有旧暗区；原厂与自定义条件均为零时，客体帧仍被压暗。此失败促成 v40 的旧像素清除，不交付 v39。
- v37 的文件查询隔离通过原生测试，但用户机身复测仍失败，不应继续称其解决了回放问题。
