## 新定位的原厂表与调用链

此前运行时影子表覆盖 `0x115A4D4C` 起的主图几何，未覆盖以下预览表：

- `0x1020C02E(index)` 返回 `0x115A4CFC + index*4`，索引 1 为 640×360。
- `0x1020C038(index)` 返回 `0x115A4D10 + index*4`，索引 1 为 1920×1080。
- `0x1020C042(index)` 返回 `0x115A4D24 + index*4`，包含不同缩略图尺寸。
- `0x1020C056()` 返回固定 160×120。样片包含的缩略图尺寸与之相符，但这不是调用身份的证明。
- `0x101434F8`、`0x10143540` 和 `0x1014363C`、`0x1014366C` 调用两份预览尺寸选择器；索引来自捕获信息 `+0x226`，不同于主图区域字段 `+0x208`。
- `0x101438D6` 是大预览缓冲区配置中的另一个调用点。
- `0x10221B54..0x10221B68` 对不同图像类型分别查询小预览、大预览、固定缩略图。

这些地址经原厂 C1.20 Thumb 指令解码核对。

## v3 预览修正

两份预览使用每个比例独立的只读尺寸对。按实际量化后的 L 主图比例，在原厂 640×360 / 1920×1080 缓冲区范围内等比容纳，并量化到 4 像素。XPAN 的两份预览目标分别为 640×236、1920×708。量化存在小幅比例误差，不对主图增加裁切或遮幅。

仅在自定义比例有效、用户原厂区域为 area 2、预览索引为 1，且返回地址匹配已定位的拍摄缓冲区/几何调用点时使用新尺寸。一般文件编辑/布局消费者返回原厂指针，不用当前拍摄档位重解释旧照片。原厂预览缓冲区分配上限保留，输出尺寸不超过该上限。

固定 160×120 缩略图通路暂时保持原厂实现。本轮目标为两份内嵌预览和普通单张回放；缩略图列表、历史照片和特殊处理模式未通过实机验证。已有照片中的预览不会由升级自动重写。

## 验收边界

原厂调用点、尺寸守卫、关闭/区域对照、缓冲区写入和主图回归由本地 ARM 执行验证；不是传感器、缩放器或 JPEG 编码执行证明。v3 仍须重新拍摄并检查实际两份预览和机内回放。

本地分析结果位于 `build/research/aspect-playback/`；v3 验证结果位于 `build/research/aspect-preview-fix/`。不在版本库保存用户照片或完整 EXIF。

验证记录：1680 项预览选择器/调用点/原厂区域/档位守卫、7 组原厂缓冲区写入、63 项主图几何、36 项参考框与 36 项驱动提交通过；QEMU 中文菜单 4:3 → XPAN → 关闭通过，59 项项目测试通过。六组主图影子表的两个区间与 v2 字节一致。以上均不等同于本版实机预览验证。

## v3 实机反馈：普通回放仍拉伸，放大后正常

用户报告 v3 普通回放仍纵向拉伸，但放大回放正常。v3 的实际回放修复未通过验收，不能把本地尺寸查询、缓冲区和菜单测试当作功能完成。

这将问题缩小到普通回放的预览/布局路径；主图和放大路径保持现状。尚不能只凭屏幕现象判断 v3 文件内预览是否已生成 640×236 / 1920×708，还是仍为 640×360 / 1920×1080。需要 v3 新拍原始 JPEG 的流尺寸和元数据作为分界证据，再决定修正捕获生成还是普通回放显示矩形。

静态补充发现：`0x1157223C` / `0x11572264` 还存在独立的小/大尺寸表，邻接 stride 表 `0x11572250`。已找到原厂代码的直接基址引用（如 `0x101431E4`、`0x10143B80`、`0x101468F4`）。目前未证明这些表是实际回放拉伸的原因，不修改它们，也不直接移除 v3 调用点保护去影响旧照片。

下一步复现必须以普通回放与放大的差异为对照，按照片自身几何适配，不能以当前 XPAN 菜单设置全局遮盖旧照片。

## v3 新样片与 v4 独立缓冲区路径

用户提供 v3 新拍样片后，扫描得到主图 5568×2056、缩略图 160×120、两份预览仍为 640×360 和 1920×1080。因此 v3 没有把预览尺寸落实到文件中；不能直接认定仅剩回放显示矩形问题。

新定位并覆盖三个完整原厂缓冲区构造函数：`0x10142D86`、`0x1014376E`、`0x101464C4`。它们通过 PC 相对字面量直接读取 `0x1157223C` / `0x11572264`，不经过 v3 的预览 getter。后一个函数使用不同捕获记录字段 `+0x4E8`，且将 LR 当普通数据寄存器使用，跳板必须保留它。

v4 给这些调用点增加同一配置下的只读尺寸副本，只有索引 1 的两对宽高变化，原厂行跨度表保持字节不变。五处跳板分别位于 `0x10142DE4`、`0x10142E46`、`0x101437A2`、`0x1014651C`、`0x10146552`。寄存器和下一条指令的衔接按完整原厂函数执行验证，不全局替换共享常量，也不修改已有照片。

`tools/verify_aspect_preview_producers.py` 对 v3 执行同样的完整函数，复现它仍产生原厂预览几何；对 v4 执行六比例、关闭、非法档位、三个用户区域和五种预览索引，共 360 项，非目标情况与原厂完整结构逐字节一致。XPAN 的两份目标为 640×236 / 1920×708。固定 160×120 缩略图仍保持原厂实现。

证据：`build/research/aspect-preview-fix-v4/producer-verification.json`。这是完整缓冲区函数执行，不是 JPEG 编码或实机回放成功证明。v4 更新后仍需新拍一张，核对文件内嵌预览和机内单张回放；主图裁切和放大路径维持原有实现。
