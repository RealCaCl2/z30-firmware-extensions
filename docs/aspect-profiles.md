## 当前使用方式（v42，2026-10-18）

`aspect-profiles` 是同一个自定义画幅预设，同时包含照片裁切和半透明取景遮幅；默认 `full` 包含它。遮幅按当前比例压暗成片范围外的区域，强度为 `128/255`（约 50%），内部网格与原厂图标保留；关闭网格仍显示遮幅，选择“关闭”恢复原厂画幅并清除遮幅。

设置 → 自定义菜单 → 照片画幅：关闭、4:3、5:4、2:1、2.35:1、2.39:1、65:24 XPAN。当前菜单按照片画幅、视频码率、快门声音、SD 卡功能分类；声音操作集中在子菜单。仅显示所选预设具备的分组。

4:3／5:4 通过对应源窗口裁切保留完整 DX 高度；宽幅裁切上下，均不应通过挤压整幅改变物体比例。沿用原厂图像区域联动、JPEG 与内嵌预览尺寸修正；L/M/S 输出尺寸见下方历史尺寸表。原厂菜单仍显示 16:9，扩展菜单显示所选比例。RAW/NEF、全部组合和生命周期没有逐项穷举证明。

```powershell
python patch.py full --source Z_30_0120.bin --output output/EG209020-full.BIN
python patch.py aspect-profiles --source Z_30_0120.bin --output output/EG209020-aspect.BIN
```

两条命令都默认包含动态遮幅，无需单独的遮幅预设或试验开关。单独画幅预设自动包含声音菜单框架。输出必须使用新路径；构建生成独立 EG 模块，不写相机或存储卡。普通构建不记录或导出诊断日志；研究 API 可显式关闭遮幅作对照，旧黄框/静态试验工具不属于普通构建流程。

v42 保留约 50% 强度与补缝，增加原厂界面阶段限制并提前清理旧遮幅，避免当前拍摄比例影响旧照片回放。用户在本次回放复测后反馈“正常了”；没有逐档明细或完整缓存/电源/HDMI 覆盖。固定已测产物与证据见 [v42](aspect-lifecycle-v42.md)，交接见 [aspect-handoff.md](aspect-handoff.md)。本次预设整合的默认构建及回归另见[验证记录](verification.md)。

## 菜单与状态

设置 → 自定义菜单 → 照片画幅，提供关闭、4:3、5:4、2:1、2.35:1、2.39:1、65:24 XPAN。同一份 EG 可切换所有比例，`*` 标记当前选择。提供简体中文、繁体中文和英文文字资源。菜单标题统一为“照片画幅”／“照片畫幅”／“Photo aspect”，去掉原有“实验”／“trial”后缀。

启用时，通过原厂设置 API 将用户图像区域属性 `0x501` 设为 area 2（原厂显示 16:9）；关闭时恢复启用前的 DX、16:9 或 1:1。原厂图像区域菜单仍使用原来的档位名称，扩展菜单显示自定义比例。已关闭时再次选择关闭，不改变用户当前区域。

大／中／小继续决定输出分辨率。自定义比例依赖原厂 area 2；启用后若手动把原厂图像区域改回 DX 或 1:1，自定义几何和参考框将不生效，空闲时重新进入照片画幅子菜单会同步回 16:9；也可重新选择比例。

选择与前一区域保存到独立 `WL-ASPECT.CFG`，检查魔数、范围、长度与校验；短写或关闭失败显示既有错误页。**配置在首次进入自定义菜单初始化时恢复；开机后尚未进入菜单之前，扩展按关闭处理。** 运行时用一个选择字读取只读比例副本，不在切换时改写原厂 ROM 表。

默认 `full` 包含全部八项功能，多画幅与声音、视频码率和 SD 模块菜单共存；显式 `full aspect-profiles` 与 `full` 启用相同功能集合。

## v2 修正：预览与出图状态不一致

第一版误写内部派生属性 `0x189e`，用户图像区域 `0x501` 仍为 DX。QEMU 原厂属性 API 已证明这两项可独立保存，写前者不会设置后者。v2 改为写入并回读 `0x501`，参考框判断也使用同一属性，不直接写派生属性。

原厂尺寸查询代码块 `0x105A7946..0x105A7974` 回归复现：旧写法在 XPAN 下仍返回 5568×3712；修正后的菜单动作让该原厂查询分别返回 L 5568×2056、M 4176×1544、S 2784×1024。这验证属性到尺寸查询的路径，尚不等同于 JPEG 编码、落盘成功。

配置魔数升级为 WLA2，避免把旧版保存的派生状态当作用户区域恢复。旧配置会被忽略，更新后需重新选择比例。

修正版证据在 `build/research/aspect-jpeg-fix/`：`native-verification.json`、`property-probe/`、`grid-driver-verification.json` 和 `qemu-hans/`。

窄幅按 DX 源窗口投影到原厂快照 viewport，不再内接比例；屏外的上/下成片边界不画成假边框。此改动不显示原厂窗口已裁掉的完整 DX 高度，也不是独立 GPU 图层；详见[映射说明](aspect-frame-grid.md)。没有主机加工图冒充取景截图。

## 构建与复现

当前功能已获用户实机确认，可通过独立预设或默认 full 构建。构建器不连接相机、刷写或写物理卡。需要项目既有 Keystone 依赖，输出路径必须尚不存在：

```powershell
python patch.py aspect-profiles --source Z_30_0120.bin --output build/research/aspect-menu/local-trial.eg.bin

```

执行验证需要 Unicorn；`--deps` 指向本地依赖目录：

```powershell
python tools/verify_aspect_profiles.py --deps ../tools/vendor --source Z_30_0120.bin --image build/research/aspect-menu/aspect-menu.eg.bin --report build/research/aspect-menu/aspect-menu.json --output build/research/aspect-menu/native-verification.json
python tools/verify_aspect_grid_device.py --research-tools ../tools --deps ../tools/vendor --input build/research/aspect-menu/native-verification.json --output build/research/aspect-menu/grid-driver-verification.json
```

驱动项复用本地父目录研究 fixture，记录源码摘要；没有该目录的独立克隆不能宣称复现驱动项。

QEMU 工具 [verify_aspect_menu_qemu.py](../tools/verify_aspect_menu_qemu.py) 接受 `--qemu-root`、`--image`、`--report`、SD 服务 `--fixture`、`--output-dir` 和 `--language`。注入仅在研究客体中发生，标准原厂 ROM 身份检查保持启用。
