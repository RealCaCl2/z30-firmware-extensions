# 自定义画幅 NEF 普通回放尺寸修正（v43）

适用 Nikon Z30 C1.20。2026-10-28，本次 XPAN RAW 普通回放花屏修复获机身复测正常反馈；未提供其他画幅或逐项操作明细。修复默认包含在原有 `aspect-profiles` 预设中，`full` 同样包含，无需新增开关。

## 问题与依据

用户反馈 XPAN 拍摄的 RAW 普通回放花屏，放大正常；关闭当前画幅后回放同一照片仍异常。原始 NEF 中三份 JPEG 分别为 640×236、1920×708、5568×2056，完整解码和目视检查正常；固定 160×120 RGB 缩略图正常。RAW IFD 为 5600×2072，尚未解码 RAW 像素，不能据此保证 RAW 数据完整。

原厂 `0x10340C84` 文件尺寸准备与 `0x103472DE` 回放描述符准备存在按画幅编号填写小/大预览尺寸的分支。自定义 XPAN 文件不符合原厂有限的画幅枚举：普通分支会填写 640×360 / 1920×1080，部分其他分支还会按主图比例重新分类。文件中的 JPEG 正常不代表机身使用了正确的缓冲区尺寸。

这是一处静态分析和原生 ARM 执行确认的尺寸不一致；本次机身复测反馈正常，但没有捕获实际回放调用轨迹，也未穷举其他花屏原因。

## 修正

`aspect_raw_playback.py` 为两个原厂尺寸填写函数和描述符打包函数安装入口跳板，仅允许已核对的文件准备调用点进入新路径。

- 仅处理原厂文件类型 1/2、主图尺寸匹配现有六种自定义画幅的文件，包含 L 主图对应的 RAW 平面边缘尺寸。
- 在文件准备阶段调用原厂 `0x103A1FA8` 服务，读取该文件小预览（种类 4）和大预览（种类 5）的尺寸，同时修正尺寸记录和解码输出描述符。
- 不根据当前拍摄档位推算预览大小。早期自定义照片如仍包含原厂 16:9 预览，继续按它们自己的预览尺寸处理。
- 查询失败、零尺寸、超出原厂预览容量或其他调用点保留原厂路径；不改写照片，不更改主图裁切、缩略图、取景遮幅或放大图像的数据。
- 新查询发生在原厂文件准备阶段，不在 GPU 提交钩子中执行。额外文件查询的延迟、其他存储卡行为和完整机身生命周期未逐项测量。

## 本地验证

`tools/verify_aspect_raw_playback.py` 执行完整原厂 `0x103472DE` 和 `0x10340C84` 函数，同时执行新增 ARM 跳板、尺寸检查和回退路径。解析后的文件记录和文件查询服务为明确夹具；可通过 `--sample` 核对输入 NEF 的实际 JPEG 流尺寸。

覆盖自定义尺寸、RAW 平面尺寸、原厂 DX/16:9、非目标尺寸、非目标类型、三个原厂分支、早期 16:9 预览、查询失败和畸形尺寸。验证记录绑定产物 SHA-256；JPEG 硬件解码、真实文件服务、自然进入相册和物理显示未在此工具中执行。

发布范围在干净源码副本中验证：`aspect-profiles` 和 `full` 均成功构建、CRC 为 0，55 项已入库项目测试通过。独立画幅构建另外通过 486 组原生描述符配置、12 组完整尺寸准备、32 组调用点尺寸查询、10 组无效查询回退，以及 63 组既有几何与 36 组参考线检查。

干净源码的 `full` 构建与本次获机身正常反馈的固件逐字节一致。固件、样片、完整 EXIF 和生成的验证报告不随源码发布，仅保留去标识化尺寸与验证范围。

## 构建与后续复测范围

沿用现有预设与构建命令：

```powershell
python patch.py aspect-profiles --source Z_30_0120.bin --output output/EG209020-aspect.BIN
python patch.py full --source Z_30_0120.bin --output output/EG209020-full.BIN
```

报告 `features.aspect_profiles.raw_preview_playback.version` 为 1。报告中的 `physical_playback_verified=false` 保留离线构建器的验证边界，不自动把一次机身反馈扩展到任意重构建或所有拍摄组合。

本次 XPAN 问题已获复测正常反馈。后续覆盖仍应包括普通回放 → 放大 → 缩回、当前画幅切为关闭、XPAN 新拍 RAW、原厂 DX RAW、普通 JPEG，以及其他自定义比例、返回取景和电源生命周期。未提供逐项反馈的项目不计为已验收。
