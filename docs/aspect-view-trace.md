## 实机对照步骤

1. 载入 v15，先将照片画幅设为关闭并重启，让第一次启用有明确起点。
2. 首次进入照片画幅选择 **4:3**，退出菜单查看取景；若出现挤压，不先待机或重启。再次进入照片画幅子菜单，空闲时会导出 `WL-ASPECT.DBG`。
3. 把这一份文件复制到电脑，命名为 `view-first.DBG`。**先保存该副本**，否则下一次导出会覆盖卡上的同名文件。复制过程若需要关机/拔卡，必须在日志已导出后进行。
4. 保持 4:3 配置重启。进入一次照片画幅子菜单恢复保存的配置，再退出菜单，确认此时是否仍正常。若配置恢复后又变形，记录这个具体转折，不能把菜单恢复前的正常画面当作“自定义 4:3 正常”。
5. 再进入子菜单导出，将文件复制为 `view-reboot.DBG`；提供这两份文件及两个状态的实际观察。对照期间先保持同一 4:3，避免同时改变画幅和启动状态。

这不是修复验收流程，而是确定首次设置与重启恢复之间的参数差异。无需为了该诊断额外拍摄照片。原始照片、EXIF、日志和运行时地址只保存在本地忽略目录，不纳入文档或版本库。

## 记录内容

日志仍叫 `WL-ASPECT.DBG`，魔数 WAD1；版本字段升到 **4**，总长 **15384 字节**：24 字节头、96 槽、每槽 160 字节。旧版 1/2/3 解码保持支持。

每个 profile 分别保留：

| 事件 | 含义 |
|---|---|
| 2 / 3 / 4 | 原有成片配置、处理请求、转换参数 |
| 5 | 进入子菜单时的用户区域、派生区域与取景缓存 |
| 6 / 7 / 8 | 三处取景窗口查询的输出尺寸和当时缓存 |
| 9 / 10 | 两处高频查询最近一次不同的尺寸状态 |
| 11 / 12 | 两处高频查询在该 profile、该 RAM 会话中的第一份状态 |

槽 0–76 对应事件 2–12，各占七个 profile；槽 77–95 是普通输出查询环。取景查询事件 6–12 只接受 profile 0/1/2。两处高频查询为 `0x10132247` 和 `0x100AEA9B`：前者补记调用者随后读取的输入 WH，后者补记随后读取的 parent WH。只在这些精确调用点按原厂后续指令已使用的字段读取，不按猜测的指针范围转储内存。

取景缓存仅采样 `0xC237C380` 中已由原厂计算使用的 full WH、area rect、buffer WH/rect、两个标志字节；**不是实际 LCD 像素、ISP/MMIO 缩放寄存器或完整视口/显示变换**。三处查询记录在选择器返回之前取得，其缓存可能尚未经过当前窗口函数后续写入；菜单事件提供后来的缓存样本，不能将两者混为同一阶段。

字段偏移用原厂 `0x10197D78` 实际写入核对：其字面量先加载 `0xC237C388`，存 full WH 后减八再存矩形。因此相对于 `0xC237C380`，full WH 在 `+0x4E/+0x50`，area rect 在 `+0x52..+0x58`；不是把两个指令所用基址直接视为相同。专用检查器执行原厂函数后验证这些值，不只依赖手工填充的缓存。

高频事件的 first 槽不会被后续顺序调用覆盖；latest 槽只在输入/输出尺寸、指针或缓存字段变化时更新，忽略保存寄存器值本身的变化。第一份状态是当前 RAM 会话首次见到该 profile 的查询，不会在每次选择时重置。快照不带统一帧号或拍摄 ID；本地夹具没有证明并发调度下的原子整帧采样。

所有查询回调只写有界 RAM 记录，不调用文件服务。文件导出仍限于空闲菜单任务，忙碌时跳过，失败时解除冻结。

## 解码与比较

```powershell
python tools/read_aspect_trace.py path/to/view-first.DBG --output build/research/view-first.json
python tools/read_aspect_trace.py path/to/view-reboot.DBG --output build/research/view-reboot.json
python tools/compare_aspect_view_trace.py path/to/view-first.DBG path/to/view-reboot.DBG --profile 1 --output build/research/view-comparison.json
```

比较器仅比较相同 profile 和相同事件的已定义字段，明确列出缺失记录。状态名称来自操作者反馈，日志不会自动判定“挤压”或“正常”。缓存相同也不能推出硬件应用的显示变换相同；差异本身不是根因判决。
