# 视频码率与慢动作限制

2026-10-17 状态更新：用户确认当前全部八项功能均已在 Nikon Z30 C 1.20 实机检验通过，包括多画幅、全信息页、声音配置记忆和机内码率档位。下文旧版本的待实机表述保留当时的测试范围，以本条为当前功能状态；离线工具的验证字段仍仅描述工具自身证据，不表示穷举全部模式、组合或故障条件。

默认 `full` 已包含 `bitrate-slowmo-uncap`，也可单独选择；旧别名 `modular` 不包含它。该预设自动包含声音菜单框架和 Keystone 依赖，在机内提供三档码率选择与 SD 配置记忆。慢动作录制上限由 3 分钟改为 25 分钟，单个 4 GB 文件限制改为与其他模式相同。分辨率、帧率、GOP、B 帧和其他模式的 125 分钟时长上限不变。

## 机内档位

打开 **设置 → 自定义菜单 → 视频码率**，选择后按确定。`*` 标记生效档位，根菜单显示当前档位。界面支持简体中文、繁体中文和英文；中文“原始”对应英文 Stock。

码率单位为 Mbps，写作“最大 / 平均”：

| 模式（高画质） | 原始（原厂） | 均衡 | 高质量（默认） |
| --- | --- | --- | --- |
| 1080 60p、50p | 56 / 48 | 84 / 70 | 108 / 90 |
| 1080 30p、25p、24p | 28 / 24 | 48 / 40 | 72 / 60 |

4K、120p/100p、慢动作和全部标准画质档的码率保持原厂值。

档位复制到后续原厂录像配置，不修改正在运行的编码器。原厂剩余时间估算与编码参数读取共用同一个记录函数；卡速、实际压缩码率与剩余时间仍需实机核验。“原始”仅恢复码率，不撤销以下慢动作限制扩展。

选择保存到 SD 根目录 `WL-VIDEO.CFG`，与声音配置 `WL-SOUND.CFG` 相互独立。记录为 16 字节：`WLB1`、保留字段零、档位编号 0–2、前三字段 XOR 的按位取反。首次打开自定义菜单或读取录像参数时恢复，无需先进入菜单；缺失、损坏、超长、错误版本或越界编号使用高质量档。保存失败在独立正文提示“设置保存失败”，当前 RAM 选择仍可用于后续录像，但不能视为重启后已保存。写入中断可能使下次恢复回到默认高质量。

| 慢动作限制 | 原厂 | 修改后 |
| --- | --- | --- |
| 录制时长上限 | 3 分钟 | 25 分钟 |
| FAT32 卡 | 1 个文件，最大 4 GB | 与 120p/100p 相同，最多 8 个文件 |
| exFAT 卡 | 1 个文件，最大 4 GB | 与其他模式相同，单个大文件 |

要自定义高质量档，在 `src/z30_extensions/features/bitrate_slowmo_uncap.py` 的 `BITRATES_MBPS` 中修改或添加行后重新构建；均衡档定义在 `bitrate_ui.py` 的 `BALANCED_MBPS`。每行是模式的最大、平均码率，模式名见 `STOCK_MBPS`。构建要求 0 < 平均 ≤ 最大 ≤ 400 Mbps：编码器以 16 位保存“最大 kbit / 8”，约 536 Mbps 溢出，取 400 留出余量。报告 `features.bitrate_slowmo_uncap` 记录默认高质量修改和慢动作上限，`features.bitrate_profiles` 记录运行时函数、档位、菜单及配置文件。

## 实现证据

地址针对未修改 Z30 C 1.20 EG，BASE 为 `0x10020000`：

| 原厂位置 | 已核对的行为 |
| --- | --- |
| `0x10713154` | 视频模式表，30 条记录，每条 `0x1C` 字节：宽、高、时间基、帧时长、M、N（GOP），`+0x14` 为最大码率，`+0x18` 为平均码率（u32，bps）。记录 20–23 是 Z30 菜单中没有的 720p 行 |
| `0x1035566C` / `0x10355754` | 由尺寸、帧率、画质得到记录序号 / 复制一条记录；后者有 6 个调用方，包括剩余时间估算、编码参数和封装器配置 |
| `0x102DFBFE` | 编码器打开函数，接收平均和最大码率；配置结构 `+0x42` 以 16 位保存最大 kbit / 8 |
| `0x10290398` | 时长上限读取函数。慢动作不查表，返回字面量 `0x10290428` 处的 180,000 ms |
| `0x10290226` | 文件数读取函数。慢动作在 `0x1029023A` 的分支直接返回 1；去掉后与 120p/100p 读同一张按模式的文件数表（8 个） |
| `0x102A1F56` | 录制器配置。`0x102A1FE6` 的分支让慢动作跳过大文件标志（配置 `+0x54`）；`0x102AC006` 在该标志置位时使用约 1 TiB 的文件大小上限，否则为 `0xFFFF0000` |
| `0x10290408` | 封装器自身的 125 分钟上限（7,501,000 ms），经 `0x102AD90E` 换算为最大帧数，超出的帧不再写入。本功能不修改 |

默认高质量数据与慢动作仍有 8 处原位替换：5 条码率记录各 8 字节，慢动作时长字面量 4 字节，两条分支各替换为一条 `nop`。新增钩子替换 `0x10355754` 的完整 10 字节指令窗口，执行原厂模式索引选择及 28 字节复制，再从当前档位表覆盖输出记录的两个码率字段；其余字段保持原厂值。三档均包含完整 30 条记录，未使用的 720p 记录也保留。菜单与设置代码使用私有追加区和状态分配，不写活动编码器对象。

时长字面量在拍摄模式属性为 `0x12` 时也会返回；Z30 的模式拨盘不提供该模式，且它仍保留单个 4 GB 文件的限制。

所有模式都是 H.264 High、CAVLC；本功能不改变编码参数，只改变码率。MOV 和 MP4 共用同一个封装器。

## 运行时档位验证

`tools/verify_bitrate_profiles.py` 执行追加 ARM 代码和原厂模式索引选择，对三档 × 30 条记录逐字节比较，检查输出缓冲前后边界；另覆盖三个档位在新 RAM 实例中的首次参数读取恢复、六种无效配置、短写和关闭失败。共 96 项，包含未使用的 720p 行。声音和模块加载器另做回归。

复现需要匹配的原厂固件、当前构建产物和 JSON：

```powershell
python tools/verify_bitrate_profiles.py --source ../Z_30_0120.bin --image output/bitrate-profiles/full.eg.bin --report output/bitrate-profiles/full.json --output build/bitrate-profiles/arm.json
```

QEMU 使用现有 `nikon-z30-display` 辅助启动机型和原厂菜单/图形管线；测试工具显式替换 SD 打开、读写和关闭服务，不能解释为真实 SD 卡、编码器输出或自然启动验证。原厂记录读取仍执行真实模式索引与字段复制代码。

```sh
python3 tools/verify_sound_settings_qemu.py --prepare-fixture build/bitrate-profiles/sd-fixture.json
python3 tools/verify_bitrate_profiles_qemu.py --qemu-root ../z30-qemu --image output/bitrate-profiles/full.eg.bin --report output/bitrate-profiles/full.json --fixture build/bitrate-profiles/sd-fixture.json --output-dir build/ui-qemu/bitrate-flow-hans --language zh-Hans
```

其他语言使用 `--language zh-Hant` 或 `--language en`，可加 `--representative-records`，在语言回归中只检查每档 1080 30p 高画质记录。菜单动作通过明确合成的原厂触摸输入执行；页面重建是异步的，测试在截图采样后继续操作，并要求活动页面确实转换。保存失败由独立诊断写入错误触发，检查正文提示、确定和原厂返回图标两条关闭路径。

实机仍需核验：不进入菜单直接开机录像的档位恢复、三档实际文件码率及完整性、卡速不足、无卡/卡满、保存时断电，以及连拍、休眠和录像模式切换。此前固定码率实机结果仅覆盖下文所列版本和组合。

## 时长上限的依据

封装器的索引表大小固定：块偏移表和关键帧表各 15,750 项，每个 GOP 一项，约合 131 分钟的成片（25p/50p/100p 的行为 126 分钟）。写满后的条目会覆盖相邻的表。

其他模式的 125 分钟上限因此保留。在 1080 30p MOV、exFAT 卡上试过两种放开方式，都丢失了素材：

- 只放开时长表 `0x115C737C`：录制持续 4 小时以上，但封装器丢弃 125 分钟之后的全部帧，文件停在 125 分钟。
- 同时放开封装器字面量：得到 161.9 分钟的文件，机内无法播放。块偏移表的 19,404 项中，超出 15,750 的部分覆盖了相邻的表。

继续放开需要在封装器库（`0x102CB000`–`0x102EF000`）内扩大这些表，该库尚未逆向。

慢动作的上限按录制时间计，而索引表按成片长度填充，快 4 或 5 倍：

| 模式 | 索引表写满时的录制时间 |
| --- | --- |
| 1080 30p x4 | 32.8 分钟 |
| 1080 25p x4 | 31.5 分钟 |
| 1080 24p x5 | 26.3 分钟 |

三种模式共用一个字面量，所以取 25 分钟。把它设为 125 分钟时，实机在 exFAT 卡上录制 45.5 分钟的 30p x4 得到 182 分钟的文件（327,339 帧），机内显示缩略图和时长后在播放时卡死重启：关键帧表溢出，覆盖了采样描述。封装器自身的上限没有及时拦住慢动作。

## 构建

```powershell
python patch.py bitrate-slowmo-uncap --source path/to/Z_30_0120.bin --output output/EG209020.BIN
```

输出路径必须不存在。支持与其他预设组合；单独选择也包含声音菜单框架，声音默认关闭。产物 SHA-256 以当前构建 JSON 为准，旧版仅 8 处原位修改的产物摘要不适用于新增机内档位的版本。保留原厂或之前已验证可用的固件，沿用已成功安装独立 EG 的流程。

## 实机确认

以下记录对应新增机内档位前的固定高质量码率版本。它们支持该档的参数取值，不证明新增菜单、运行时切换、均衡档、首次恢复和 SD 配置写入已经实机通过。

2026-10-11 至 2026-10-13，Z30 C 1.20。除注明 MP4 的一行外均为 MOV 格式。文件从 SD 卡直接复制或在卡上直接读取，逐项检查索引表与 mdat 是否一致。

| 测试 | 结果 |
| --- | --- |
| 1080 24p / 25p / 30p 高画质，短片段 | 实际平均码率 60.1 / 60.0 / 60.4 Mbps，文件完整 |
| 1080 50p 高画质，短片段 | 90.1 Mbps，文件完整 |
| 1080 60p 高画质，36.7 分钟、25.3 GB（exFAT） | 90.2 Mbps，文件完整 |
| 1080 30p x4 慢动作，128 GB exFAT 卡 | 25.0 分钟自动停止；单个 22.9 GB 文件，179,835 帧，成片 100 分钟，索引完整 |
| 1080 24p x5 慢动作，32 GB FAT32 卡 | 25.0 分钟自动停止；7 个约 3.73 GB 的文件，共 179,835 帧，成片 125.0 分钟；各文件索引完整，结束于完整 GOP，开始于 IDR 帧 |
| 1080 24p x5 慢动作，128 GB exFAT 卡 | 25.0 分钟自动停止；单个 22.8 GB 文件，179,844 帧，成片 125.0 分钟；索引表用到 15,750 项中的 14,987 项，索引完整 |
| 1080 25p x4 慢动作，MP4，128 GB exFAT 卡 | 25.0 分钟自动停止；单个 22.7 GB 文件，150,012 帧，成片 100.0 分钟；索引表用到 12,501 项，索引完整 |

24p x5 是三种慢动作模式里索引表余量最小的，上表的单文件结果是 25 分钟上限下的最坏情况。两个新文件的块偏移表（`co64`）、关键帧表和采样大小表与 mdat 逐字节对齐，每个关键帧表项都指向 IDR 帧。MP4 与 MOV 的索引结构相同，只有 `ftyp` 不同（`mp42` / `qt  `），与静态分析一致。

尚未实机测试：

- 普通（非慢动作）模式的 MP4 格式，以及 FAT32 卡上的 MP4 分段。
- 提高默认值以外的码率档，以及高码率下对存储卡写入速度的要求。

该结果针对包含本功能的组合产物，不代表所有预设组合均已实机验证。离线构建报告保持 `camera_verified: false`，表示脚本自身没有执行机身测试。

复查文件时，用 ffprobe 查看视频流的码率、帧数和时长：

```powershell
ffprobe -v error -select_streams v:0 -show_entries stream=bit_rate,nb_frames,duration -of json "测试视频.MOV"
```

慢动作录到上限后，帧数应接近 179,835（25p x4 为 150,012），文件可在机内正常播放。若机内无法播放，或帧数明显超过 15,750 × GOP 长度，说明索引表已溢出，需要降低 `SLOW_LIMIT_MS`。
