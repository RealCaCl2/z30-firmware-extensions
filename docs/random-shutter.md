# 可选随机快门声音

`shutter-random` 自动包含 `shutter-sound`，不包含在 `full` 中。
当前支持单独使用或与 `wifi-5ghz`、`wifi-5ghz-all-profiles` 组合；与其他扩展共享菜单的组合会明确拒绝构建。
未启用这个预设时，原有声音构建路径保持原样。

```sh
python patch.py shutter-random wifi-5ghz --source Z_30_0120.bin --output output/EG209020.BIN
```

## 使用

将 `SHUTTER/1.WAV` 至 `SHUTTER/4.WAV` 放在 SD 卡上。
每个文件须为 8 kHz、单声道、16 bit PCM、标准 44 字节 WAV 头，
非空且最长 1.08 秒；四段总容量为 4.32 秒。
原有根目录 `SHUTTER.WAV` 和四个固定选项继续可用。

首次进入“快门声音 → 声音文件 → 随机播放”，预听并开启声音，
拍照时开启原厂静音拍摄。设置保存在 `WL-SOUND.CFG`，声音与配置应留在卡上。
以后开机在应用和存储卡就绪后自动安排后台预加载，无需进入声音菜单。
更换文件后，可正常关机换卡再开机，或使用菜单“重新加载”。

多个有效文件时，每次抽选排除上一次选中的编号；选中后立即更新这个编号。
后续播放成功或失败均不改变已经记录的选择，不等待成功回调，也不回滚历史。
通过一次 N−1 索引映射跳过该项，无需创建/删除列表或反复抽选。
只有一个有效文件时重复选择它；这条规则保证相邻抽选不同，不保证被中止或失败后的听感不同。
原厂同一照片的多个阶段会共享通知入口；声音仅在 type 0 阶段触发一次，
其他阶段仍执行原厂回调，避免同一照片二次抽选并打断第一段声音。
随机算法使用固定种子的私有 xorshift32，重启后序列可能重复。
缺失或格式无效的单个文件会跳过；没有有效文件、总容量超限或读取/关闭失败时关闭随机池声音。
繁忙时拒绝重载并保留旧缓存；开始重建池后发生失败则废弃该次池状态。
设置写入 `WLS2`，并兼容读取只含固定选项 0–4 的旧 `WLS1` 配置。

## 资源与行为边界

- 保留原 PCM 槽及菜单/元数据偏移，末尾追加三个 PCM 槽，四槽合计 829,440 字节。
  随机预设的状态一次申请 847,167 字节，较未启用随机预设的声音状态增加 622,172 字节；
  在这个构建中选择固定声音也不会缩小申请量，分配失败不发布新状态。
- 复用原厂音频任务后台加载，不创建新线程。普通拍摄路径不读卡、不转换音频，
  保留原有播放任务分配；启动预加载的读取、转换和清零工作随容量增加。
- 初始化完成前不公开状态，加载前及过程中检查关机、卡状态和用户操作。
  队列提交有界，失败释放临时消息；用户操作取消尚未执行的延后声音。
- 预加载尚未完成时拍照，最多合并为一次加载后重新检查条件的延后声音，不阻塞拍照等待加载。
  连拍沿用单一 pending 标志，不保证每张都完整播放一段声音。
- 原厂文件服务没有已确认的有限等待超时；检查不能取消已经进入原厂内部的 I/O。
  指令级模拟不能替代真实机身堆内存、启动、拔卡、关机或扬声器测试。
