# 第二阶段视频自动方向

2026-10-17 状态更新：用户确认当前全部八项功能均已在 Nikon Z30 C 1.20 实机检验通过，包括多画幅、全信息页、声音配置记忆和机内码率档位。下文旧版本的待实机表述保留当时的测试范围，以本条为当前功能状态；离线工具的验证字段仍仅描述工具自身证据，不表示穷举全部模式、组合或故障条件。

默认 `full` 已包含 `video-rot`，也可单独选择；旧别名 `modular` 不包含它。新录像封装对象成功配置后，读取原厂姿态状态，锁定该对象的视频轨方向；停止录制时不重新读取姿态。仅修改视频轨方向元数据，共享原厂矩阵、电影头和音轨不变。

## 实现证据

地址针对未修改 Z30 C 1.20 EG，BASE 为 `0x10020000`：

| 原厂路径 | 已核对的行为 |
| --- | --- |
| `0x1021C7F2` | 将调用方提供的三轴数据转换到输出缓冲，不是无参数传感器读取函数 |
| `0x1021B5F6` | 读取原厂维护的方向状态，返回 0/1/2/3 或未知 4；`0x10334552` 等调用方将 0/3 视为横向、1/2 视为纵向 |
| `0x102F0260` → `0x102EF402` | 创建封装对象之后配置视频参数，成功返回 0；两个创建路径在 `0x102CAC48` 和 `0x102EA888` 调用 |
| `0x102CA2D6` / `0x102EA318` → `0x102EF254` | 收尾路径组装文件头，而不是开始录制时采样姿态的可靠位置 |
| `0x102EE814` | 视频 tkhd 构造器，通过 PC 相对地址使用共享矩阵，最终写入对象 `+0x109` 的 36 字节矩阵槽位 |
| `0x102EEF44` | 构造 mvhd，不能仅凭 issue 的函数名称把它视为视频轨 tkhd |

因此本实现不直接按 issue 第二阶段建议在 `0x102EEF4C` 读取姿态：那会在收尾时采样，且改动电影头。新钩子先让原厂配置函数执行，只有成功才在对象 `+0x109` 写入方向快照；视频 tkhd 构造器再将快照复制到原厂栈缓冲，后续字节写入由原厂完成。不借用未确认空闲 RAM，不使用全局上一段视频状态，也不新建传感器阈值。

原厂姿态 0/1/2/3 映射为 0°/90°/270°/180°，未知或不可用回退 0°。横纵分类有静态证据；用户已在实机确认横拍和两侧竖拍显示方向正确，录制中转动机身仍保持开始时的方向。Z30 不按此前通用测试建议自动分段，该项不适用于本机验证。

## 构建

```powershell
python -m pip install '.[video]'
python patch.py video-rot --source path/to/Z_30_0120.bin --output output/EG209020.BIN
```

输出路径必须不存在。支持与其他预设组合。当前本地最终测试文件在 `build/video-rot-stage2/EG209020.BIN`，SHA-256：

```text
0364ada38af88fd7ef67abdd4582b1a9761ab98077433ceede24b20d754c4eb8
```

第一阶段的固定 90° 文件不是此版本。此独立产物只含视频方向功能；保留原厂或你之前已验证可用的固件，沿用已成功安装独立 EG 的流程。

## 实机确认

2026-10-12，用户反馈横拍、两侧竖拍、录制中方向锁定均正常，并确认连续录像切换方向、重启、所用 4K/慢动作模式及声画、播放、照片基本回归正常。以下保留可复现的检查步骤。倒置横拍没有单独的实机结果记录；原始 MP4 尚未在本仓库逐字节检查。该反馈针对已测试的独立视频方向产物，不代表全部组合均已实机验证。

画面放一张标有“上 ↑”的纸，各拍约 10 秒。拍摄前先持稳，让原厂姿态状态更新：

| 测试 | 预期 |
| --- | --- |
| 正常横拍 | 保持横向，不再强制竖向 |
| 两侧分别竖拍 | 都正向竖屏；两份文件矩阵分别是 90° 和 270° |
| 倒置横拍 | 180° |
| 横拍开始，录制中转为竖拍 | 文件保持开始时横向矩阵 |
| 竖拍开始，录制中转为横拍 | 文件保持开始时竖向矩阵 |
| 停止后以另一姿态重新录制 | 新文件重新选择方向，不继承上一段 |

记录是否能正常开始、停止、回放、录音和重新开机；再分别测试你使用的 4K 和慢动作模式。照片方向也应保持原厂行为。

直接从 SD 卡复制原始 MP4，保留文件与拍摄姿态对应关系。用 ffprobe 查看视频流的 Display Matrix：

```powershell
ffprobe -v error -select_streams v:0 -show_streams -of json "测试视频.MP4"
```

编码宽高仍可为横向，因为像素没有被旋转。若两侧竖拍均写入旋转但显示倒置，需要调整 1/2 的矩阵映射；若所有视频都是 0°，需要检查实际录像配置调用和原厂姿态是否可用。若录制中转动改变了最终矩阵，需要追踪实际对象重建或重复配置时机。

单元测试、Unicorn 和 QEMU 已验证合成姿态/封装对象下的原厂函数执行与矩阵锁定；它们不模拟真实传感器或完整录制。离线构建及验证报告保持 `camera_verified: false`，表示脚本自身没有执行机身测试；实机反馈单独记录于本文，不扩大为全部组合或模式的验证。
